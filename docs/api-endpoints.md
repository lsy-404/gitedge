# API endpoints

Responses use `{ "data": ... }`; failures use `{ "error": { "code": ..., "message": ... } }`. Private repository existence is hidden from unauthorized readers.

Gateway: `GET /api/health` (anonymous, per-IP rate limited) returns `{ status: "ok" | "degraded", services: { <name>: { ok, latencyMs } } }` for `auth`, `forge`, `git`, `deploy`, `actions`, `limits` and `d1`, with HTTP 503 when any probe fails. Rate-limited requests receive 429 with a `Retry-After` header and `retryAfter` seconds in the body.

Auth: register, login, logout, session and identity-only GitHub OAuth under `/api/auth`. Account agent CRUD lives at `/api/auth/agents`; each agent's session collection lives at `/api/auth/agents/:id/sessions`. Sessions return API/Git credentials once. Account Git credentials live at `/api/auth/tokens`. Personal access tokens live at `/api/auth/access-tokens` (`GET` lists, `POST` creates, `DELETE /:id` revokes). Creation takes `{ name, scopes, expiresInDays (1-365), repositoryIds? }` and returns the `gep_` plaintext once; it requires a signed-in browser session that confirmed its identity in the last 10 minutes (otherwise 403 `reauth_required`) and is refused for Bearer tokens and agent sessions. A token is accepted as `Authorization: Bearer gep_...` on `/api/*` and as the HTTP Basic password (any username) on Git Smart HTTP. Scopes: `repo:read`, `repo:write` (implies read), `issues:write`, `pulls:write` (both imply repository read), `org:read` and `admin` (all). Services answer `403 insufficient_scope` when a request needs a scope the token lacks, and tokens limited to `repositoryIds` cannot reach other repositories. Invalid, revoked or expired tokens receive 401. SSO provider discovery, login, metadata, identity linking and single sign-out live under `/api/auth/sso`; see [SSO configuration](sso.md). Signing keys are listed, added and revoked at `/api/auth/signing-keys` (with `/signing-keys/challenges`); `/api/auth/profile` and `/api/auth/agent-profiles/:owner/:handle` expose profiles.

Account security (Auth, browser sessions only): `POST /api/auth/login` returns either the user or `{ secondFactorRequired, mfaToken, methods }`; finish with `POST /login/second-factor` (`/login/second-factor/options` prepares a passkey prompt). Passkey sign-in is `POST /login/passkey/options` then `/login/passkey`. Recovery: `GET /recovery/options`, `POST /recovery/password` (username and recovery code), `POST /recovery/email` (always 202) and `POST /recovery/email/confirm`; `POST /email/verify` spends a verification link. Signed-in management lives under `GET /security` (summary), `POST /reauth` and `/reauth/passkey/options` (confirm identity for 10 minutes), `POST /security/password`, `PUT|DELETE /security/email`, `POST /security/totp`, `/security/totp/confirm`, `/security/totp/disable`, `POST /security/recovery-codes` and `/security/passkeys[/options]` with `PATCH|DELETE /security/passkeys/:id`. Sensitive routes answer 403 `reauth_required` outside the confirmation window. See [account security](account-security.md).

Forge: `GET /api/forge/usage` returns the caller's repository count, storage use (`usedBytes` is `null` because Artifacts does not report repository size) and the limits of their user group. Creating a repository beyond the group limit returns 403 `quota_exceeded` with `error.quota` `{ resource, used, limit }`. `/api/forge/repositories`, `/repositories/by-name/:owner/:repo`, and organization/member management. Repository resources are `/repositories/:id/issues`, `/pull-requests`, `/discussions`, `/wiki`, `/settings`, `/tasks`, `/memory` (404 `feature_disabled` when tasks are off), `/assignee-candidates`, `/branch-rules` `/collaborators`, `/invitations` and `/audit-log`. Numbered items expose details, PATCH and comments. PRs expose `diff`, `reviews`, `checks` and `merge`; merge requires expected base/head OIDs. Wiki pages expose history and revision-aware PUT/restore.

Notifications (Forge, signed-in users and personal access tokens with `repo:read`; agent sessions are refused): `GET /api/forge/notifications` lists the caller's notifications newest first with `unread=true`, `repositoryId`, `reason` (`assigned`, `review_requested`, `mentioned`, `comment`, `check_failed`, `merged`, `invited`), `limit` (1-50, default 25) and the `before` cursor from the previous `nextCursor`. Each item has `reason`, `subjectKind`, `subjectNumber`, `title`, `repository`, `actor`, `createdAt` and `readAt`. Items for repositories the caller can no longer read are omitted. There is one notification per user and thread; new activity updates its reason and marks it unread again. `GET /notifications/unread-count` returns `{ unread, capped }` (counted up to 100). `POST /notifications/read` takes `{ ids }` (at most 100) or `{ all: true, repositoryId? }` and returns `{ updated }`. `GET` and `PUT /notification-preferences` read and replace `{ mutedReasons }` (tokens need `admin` to replace them); muted reasons stop new notifications only. Adding a collaborator notifies them once; later role changes do not. Read notifications are deleted after 90 days.

Repository webhooks (Forge, repository administrators only; tokens need the `admin` scope; agent sessions are refused): `GET`/`POST /api/forge/repositories/:id/webhooks`, `GET`/`PATCH`/`DELETE /webhooks/:hookId`, `POST /webhooks/:hookId/ping`, `GET /webhooks/:hookId/deliveries`, `GET /webhooks/:hookId/deliveries/:deliveryId` (includes the payload) and `POST /webhooks/:hookId/deliveries/:deliveryId/redeliveries`. Creating, updating and deleting require a browser session that confirmed its identity in the last 10 minutes (403 `reauth_required` otherwise). `POST` takes `{ url, contentType: "json", events, active, secret? }`; the URL must be HTTPS on port 443, a public DNS name that resolves only to public addresses (400 `invalid_webhook_url` otherwise). A generated secret is returned once as `secret`; supplied secrets (16-128 characters) and later reads return `secret: null`, and `PATCH` with `rotateSecret: true` generates a new one. At most 20 webhooks per repository (409 `webhook_limit`); 503 when `WEBHOOK_ENCRYPTION_KEY` is missing. Events: `push`, `issues`, `issue_comment`, `pull_request`, `pull_request_review`, `check_run`, plus `ping` for tests. Requests are `POST` with `Content-Type: application/json`, `X-GitEdge-Event`, `X-GitEdge-Delivery` and `X-Hub-Signature-256: sha256=<hex HMAC-SHA256 of the body>`. A 2xx response succeeds; anything else (redirects are not followed, responses over 4 KB fail) is retried after 1, 2, 4 and 8 minutes, five attempts in total, then marked failed. Push payloads list one delivery per ref update that receive-pack reported as accepted (at most 20 per push; `before`/`after` are all zeros for creation and deletion) and carry no commit list. Delivery bodies clip text fields at 8 KB.

Lifecycle: repository deletion, purge-now, transfer and organization deletion require a browser session that confirmed its identity in the last 10 minutes and otherwise answer 403 `reauth_required`; tokens and agent sessions cannot perform them. `DELETE /api/forge/repositories/:id` soft-deletes a repository (repository administrators; body `{ "confirm": "owner/name" }`). A deleted repository answers 404 on every route, listing, profile and Git transport path, its name is released and its agent sessions are revoked (the response flags `revocationIncomplete` when Auth could not finish; the purge retries). Until it is purged it still counts toward the creator's repository limit. It stays restorable for 7 days: `GET /deleted-repositories` lists the viewer's recently deleted repositories, `POST /deleted-repositories/:id/restore` restores one (409 if the name was reused), and `DELETE /deleted-repositories/:id` (same confirmation) purges immediately. A scheduled Forge job purges expired repositories: it revokes agent sessions through Auth, deletes the Artifacts repositories and session forks through Git, then removes the D1 rows, persisting progress in `purge_state` and the fork cursor in `purge_cursor`; a failed attempt waits an hour (`purge_retry_at`) so it cannot starve other expired repositories. `POST /repositories/:id/transfer` (`{ "owner", "confirm" }`) moves a repository from a namespace the caller owns to their own account or an organization they own; the old path keeps redirecting (web routes and Git remotes answer 308), explicit collaborators are kept, inherited access follows the new owner and agent sessions are revoked. `DELETE /organizations/:slug` (owner only, body `{ "confirm": "slug" }`) is refused with 409 `organization_not_empty` while the organization holds any repository row, including deleted ones awaiting purge.

Repository import: `POST /api/forge/repository-imports` with `sourceUrl`, `owner`, `slug`, `visibility` and `description` queues an import of a public https Git remote through the native Artifacts import and returns `202` with the job. `GET /repository-imports` lists the caller's unfinished jobs, `GET /repository-imports/:id` returns one job (`queued`, `running`, `succeeded` or `failed`, with `progress` `starting`/`importing` and `errorCode`) and advances it, and `POST /repository-imports/:id/retry` requeues a failed job. Poll the job until it is terminal: Artifacts may keep copying after it accepts the import, and the repository record exists only after the copy is ready and its initial token is revoked. Jobs are visible only to their creator, and an active import reserves its repository name. Sources must be https on the default port with a DNS hostname whose A/AAAA records are all public: IP literals, local names and embedded credentials are rejected with `422`, and hosts resolving to private, loopback, link-local or reserved ranges fail the job with `invalid_url`. Starts and retries are limited to 5 per minute per user. Personal access tokens need `repo:write` to start or retry an import and `repo:read` to read jobs or `GET /usage`.

Git: `/api/git/repositories/:id/refs`, `tree`, `file`, `raw`, `commits`, `graph` and `compare`. Reads accept appropriate `ref`, `path`, `offset` or `limit` queries. Comparisons accept `base`, `head` and a validated `headSessionId`. Agent sessions operate on their own workspace by default.

Actions: `/api/actions/repositories/:id[/...]`, `/api/actions/runs/:id` and `/api/actions/runs/:id/cancel`. Starting a run beyond six per repository per hour returns 429 `run_limit` with a `Retry-After` header.

Deploy: `/api/deploy/plan`, `session`, `account`, `resources`, `provision`, `migrate` and `deploy`. See [the deployment manifest](deploy.md) for source and permission requirements.

Invitations (Forge): collaborators and organization members join only by accepting an invitation; the earlier direct-add routes are gone. `POST /api/forge/repositories/:id/invitations` (repository administrators) and `POST /api/forge/organizations/:slug/invitations` (owners) take `{ "identifier" | "email", "role" }`. A username invitation is bound to that user and appears in their dashboard; an email invitation returns a one-time `token` (shown once, only its hash is stored) that the inviter sends as `https://<host>/invite#<token>`, so the invitee can register or sign in first and then accept. The invite page moves the token from the address into tab storage, so sign-in and registration return addresses never carry it. Invitations expire after 7 days, each target holds at most 50 pending ones, a repository holds at most 80 explicit collaborators (409 `member_limit` when inviting or accepting beyond it), `GET .../invitations` lists them and `DELETE .../invitations/:invitationId` cancels one. Invitees use `GET /api/forge/invitations` and `POST /invitations/:id/accept|decline` (bound to the invited user; anyone else gets 404), or `POST /invitations/lookup|accept|decline` with `{ "token" }`. Accepted invitations grant the role atomically; closed, cancelled and expired ones answer 409 `invitation_closed`. Existing explicit collaborators change role with `PATCH /repositories/:id/collaborators/:userId` and organization members with `PATCH /organizations/:slug/members/:identifier`. Personal access tokens need the `admin` scope for these writes, and tokens restricted to specific repositories cannot use the account-level invitation routes.

Audit log: `audit_events` is append-only (database triggers reject updates and deletes). Events are recorded for visibility changes, renames, archive changes, repository delete, restore, purge request and transfer, branch rules, collaborator and member changes, invitations, merges, agent webhook changes, access token create and revoke, authenticator, passkey, recovery code and password changes, account export and deletion, and site administration. Each entry stores the actor (user, agent with its session, or personal access token with its id), target, repository or organization and bounded metadata; credential-like keys and values are dropped before storage. `GET /api/forge/repositories/:id/audit-log` (repository administrators), `GET /api/forge/organizations/:slug/audit-log` (owners) and `GET /api/auth/audit-log` (the signed-in user's own security events) return `{ events, nextCursor }` newest first; pass `cursor` and `limit` (at most 100) to page.

Site administration (Auth, browser sessions of site administrators only; tokens and agents get 403): `GET /api/auth/admin/users?q=&cursor=`, `/admin/repositories`, `/admin/groups` and `/admin/stats` read; `POST /admin/users/:id/disable|enable` and `PATCH /admin/users/:id` (`groupKey`, `siteAdmin`) mutate and need a confirmation from the last 10 minutes (403 `reauth_required`). Site administrators cannot be disabled (409) until their stored flag is removed, and administrators named in `SITE_ADMINS` cannot be disabled at all. Disabling ends the user's browser sessions and revokes their agent sessions; the response flags `revocationIncomplete` when an agent session could not be revoked yet. A disabled account is rejected wherever Auth validates credentials: browser sessions, personal access tokens, agent sessions, Git credentials, password, passkey, GitHub and SSO sign-in (403 `account_disabled` at sign-in).

Account data (Auth, browser sessions with a recent confirmation): `GET /api/auth/account/export` streams a JSON archive with the profile, organizations, repository metadata, and the issues, pull requests, discussions, comments and reviews the user wrote, plus access token, Git credential and agent metadata without hashes. Each collection is capped at 2000 entries and the final `truncated` array names any that were cut. `POST /api/auth/account/delete` takes `{ "confirm": "<username>" }`; it answers 409 `organization_ownership` while the user is the only owner of an organization that has other members or repositories. Deletion revokes sessions, tokens, credentials and the user's agent sessions as well as every agent session on the user's personal repositories (503 with nothing changed when Artifacts cannot revoke one yet), cancels pending invitations, removes memberships, deletes organizations the user alone belongs to that hold no repositories, and soft-deletes repositories in the personal namespace for immediate purge; personal repositories already awaiting purge lose their restore window. The username stays reserved.
