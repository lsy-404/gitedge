# API endpoints

Responses use `{ "data": ... }`; failures use `{ "error": { "code": ..., "message": ... } }`. Private repository existence is hidden from unauthorized readers.

Gateway: `GET /api/health` (anonymous, per-IP rate limited) returns `{ status: "ok" | "degraded", services: { <name>: { ok, latencyMs } } }` for `auth`, `forge`, `git`, `deploy`, `actions`, `limits` and `d1`, with HTTP 503 when any probe fails. Rate-limited requests receive 429 with a `Retry-After` header and `retryAfter` seconds in the body.

Auth: register, login, logout, session and identity-only GitHub OAuth under `/api/auth`. Account agent CRUD lives at `/api/auth/agents`; each agent's session collection lives at `/api/auth/agents/:id/sessions`. Sessions return API/Git credentials once. Account Git credentials live at `/api/auth/tokens`. Personal access tokens live at `/api/auth/access-tokens` (`GET` lists, `POST` creates, `DELETE /:id` revokes). Creation takes `{ name, scopes, expiresInDays (1-365), repositoryIds? }` and returns the `gep_` plaintext once; it requires a signed-in browser session that confirmed its identity in the last 10 minutes (otherwise 403 `reauth_required`) and is refused for Bearer tokens and agent sessions. A token is accepted as `Authorization: Bearer gep_...` on `/api/*` and as the HTTP Basic password (any username) on Git Smart HTTP. Scopes: `repo:read`, `repo:write` (implies read), `issues:write`, `pulls:write` (both imply repository read), `org:read` and `admin` (all). Services answer `403 insufficient_scope` when a request needs a scope the token lacks, and tokens limited to `repositoryIds` cannot reach other repositories. Invalid, revoked or expired tokens receive 401. SSO provider discovery, login, metadata, identity linking and single sign-out live under `/api/auth/sso`; see [SSO configuration](sso.md). Signing keys are listed, added and revoked at `/api/auth/signing-keys` (with `/signing-keys/challenges`); `/api/auth/profile` and `/api/auth/agent-profiles/:owner/:handle` expose profiles.

Account security (Auth, browser sessions only): `POST /api/auth/login` returns either the user or `{ secondFactorRequired, mfaToken, methods }`; finish with `POST /login/second-factor` (`/login/second-factor/options` prepares a passkey prompt). Passkey sign-in is `POST /login/passkey/options` then `/login/passkey`. Recovery: `GET /recovery/options`, `POST /recovery/password` (username and recovery code), `POST /recovery/email` (always 202) and `POST /recovery/email/confirm`; `POST /email/verify` spends a verification link. Signed-in management lives under `GET /security` (summary), `POST /reauth` and `/reauth/passkey/options` (confirm identity for 10 minutes), `POST /security/password`, `PUT|DELETE /security/email`, `POST /security/totp`, `/security/totp/confirm`, `/security/totp/disable`, `POST /security/recovery-codes` and `/security/passkeys[/options]` with `PATCH|DELETE /security/passkeys/:id`. Sensitive routes answer 403 `reauth_required` outside the confirmation window. See [account security](account-security.md).

Forge: `GET /api/forge/usage` returns the caller's repository count, storage use (`usedBytes` is `null` because Artifacts does not report repository size) and the limits of their user group. Creating a repository beyond the group limit returns 403 `quota_exceeded` with `error.quota` `{ resource, used, limit }`. `/api/forge/repositories`, `/repositories/by-name/:owner/:repo`, and organization/member management. Repository resources are `/repositories/:id/issues`, `/pull-requests`, `/discussions`, `/wiki`, `/settings`, `/tasks`, `/memory` (404 `feature_disabled` when tasks are off), `/assignee-candidates`, `/branch-rules`, `/collaborators` and `/releases`. Numbered items expose details, PATCH and comments. PRs expose `diff`, `reviews`, `checks` and `merge`; merge requires expected base/head OIDs. Wiki pages expose history and revision-aware PUT/restore.

Lifecycle: repository deletion, purge-now, transfer and organization deletion require a browser session that confirmed its identity in the last 10 minutes and otherwise answer 403 `reauth_required`; tokens and agent sessions cannot perform them. `DELETE /api/forge/repositories/:id` soft-deletes a repository (repository administrators; body `{ "confirm": "owner/name" }`). A deleted repository answers 404 on every route, listing, profile and Git transport path, its name is released and its agent sessions are revoked (the response flags `revocationIncomplete` when Auth could not finish; the purge retries). Until it is purged it still counts toward the creator's repository limit. It stays restorable for 7 days: `GET /deleted-repositories` lists the viewer's recently deleted repositories, `POST /deleted-repositories/:id/restore` restores one (409 if the name was reused), and `DELETE /deleted-repositories/:id` (same confirmation) purges immediately. A scheduled Forge job purges expired repositories: it revokes agent sessions through Auth, deletes the Artifacts repositories and session forks through Git, then removes the D1 rows, persisting progress in `purge_state` and the fork cursor in `purge_cursor`; a failed attempt waits an hour (`purge_retry_at`) so it cannot starve other expired repositories. `POST /repositories/:id/transfer` (`{ "owner", "confirm" }`) moves a repository from a namespace the caller owns to their own account or an organization they own; the old path keeps redirecting (web routes and Git remotes answer 308), explicit collaborators are kept, inherited access follows the new owner and agent sessions are revoked. `DELETE /organizations/:slug` (owner only, body `{ "confirm": "slug" }`) is refused with 409 `organization_not_empty` while the organization holds any repository row, including deleted ones awaiting purge.

Repository import: `POST /api/forge/repository-imports` with `sourceUrl`, `owner`, `slug`, `visibility` and `description` queues an import of a public https Git remote through the native Artifacts import and returns `202` with the job. `GET /repository-imports` lists the caller's unfinished jobs, `GET /repository-imports/:id` returns one job (`queued`, `running`, `succeeded` or `failed`, with `progress` `starting`/`importing` and `errorCode`) and advances it, and `POST /repository-imports/:id/retry` requeues a failed job. Poll the job until it is terminal: Artifacts may keep copying after it accepts the import, and the repository record exists only after the copy is ready and its initial token is revoked. Jobs are visible only to their creator, and an active import reserves its repository name. Sources must be https on the default port with a DNS hostname whose A/AAAA records are all public: IP literals, local names and embedded credentials are rejected with `422`, and hosts resolving to private, loopback, link-local or reserved ranges fail the job with `invalid_url`. Starts and retries are limited to 5 per minute per user. Personal access tokens need `repo:write` to start or retry an import and `repo:read` to read jobs or `GET /usage`.

Git: `/api/git/repositories/:id/refs`, `tree`, `file`, `raw`, `commits`, `graph`, `compare`, `tags` and `archive`. Reads accept appropriate `ref`, `path`, `offset` or `limit` queries. Comparisons accept `base`, `head` and a validated `headSessionId`. Agent sessions operate on their own workspace by default.

Tags: `GET /api/git/repositories/:id/tags` lists up to 100 tags (natural order, newest name first) with `{ name, oid, commitOid, annotated, subject, timestamp }` and `truncated`; `?name=` returns one tag. `POST` takes `{ name, target, source?, message? }` where `target` is a branch name (the tag points at its tip) or a full commit id contained in `source` (default: the default branch); a `message` makes the tag annotated. `DELETE` takes `{ name, expectedOid }`. Both need repository write access (`repo:write` for tokens), refuse archived repositories and agent sessions, and answer 409 `tag_exists` or `refs_changed` on conflicts. Branch protection rules match branch names only, so tags need write access and nothing more. Creating a tag clones the source branch into memory and shares the Git service's 24 MiB transfer limit (413 `operation_limit` beyond it).

Raw files: `GET /:owner/:repo/raw/:ref/:path` (also `HEAD`) is served by the Gateway from the Git API (`/api/git/repositories/:id/raw?spec=<ref>/<path>` or `?ref=&path=`). The ref may contain slashes (the longest matching branch or tag wins) and may be a commit id or `HEAD`. Text renders inline as `text/plain`, images (PNG, JPEG, GIF, WebP, AVIF, BMP, ICO, SVG) inline with their own type, and everything else downloads as `application/octet-stream`; `?download=1` always downloads. Every response carries `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox` and an `ETag` equal to the blob id (`If-None-Match` answers 304). Public repositories send `Cache-Control: public` (`max-age=300` when the ref is a commit id, otherwise revalidate every time); private repositories send `private, no-store` and answer 404 to readers without access. Files above 64 MiB answer 413 `file_too_large`.

Source archives: `GET /:owner/:repo/archive/:ref.zip` and `.tar.gz` (Git API: `archive?ref=&format=zip|tar.gz`) stream the tree of a branch, tag or commit under a single `<repo>-<ref>/` folder; symlinks and executable bits are kept and submodule links are omitted. The tree is walked before streaming: more than 5,000 files, 1,000 directories or 64 levels answers 413 `archive_too_large`, and unsafe paths answer 422 `archive_invalid`. Byte limits (128 MiB uncompressed, 32 MiB per file) are enforced while streaming, so exceeding one aborts the transfer instead of ending a valid but incomplete archive. `ETag` is the commit id plus format. Because an archive reads every tree and blob from Artifacts, the Gateway allows 10 archive requests per minute per user (per IP address for anonymous readers) on both URLs, on top of the normal request limits, and answers 429 with `Retry-After` beyond that.

Releases: `GET /api/forge/repositories/:id/releases` lists up to 100 releases (`truncated` flags more), `GET .../releases/latest` returns the newest published non-pre-release (404 when none) and `GET .../releases/:releaseId` one release; anonymous readers can read public repositories, and drafts are visible to members with write access only. `POST` takes `{ tagName, target?, source?, title?, body?, draft?, prerelease? }`: publishing creates the tag from `target` through the Git service when it does not exist (an existing tag is reused as it is and the release's `target` is then `null`; a missing tag without `target` answers 400 `tag_missing`), while a draft creates the tag when it is published. `PATCH` updates `title`, `body`, `prerelease` and `draft` (the tag name is fixed); a publish or unpublish that races another one answers 409 `release_changed`, so each publication emits one event. `DELETE` removes the release and its assets but keeps the tag. Writes need repository write access (`repo:write` for tokens), exclude agent sessions, and deleting a release from a browser session requires a recent identity confirmation (403 `reauth_required`). A repository holds at most 1,000 releases.

Release assets are stored in the `RELEASE_ASSETS` R2 bucket bound to Forge. `PUT .../releases/:releaseId/assets?name=<file>` streams the raw request body straight to R2: send `Content-Length` (411 `length_required` otherwise) and optionally `Content-Type`. Files are limited to 100 MiB (413 `asset_too_large`, checked before the body is read), a release holds 50 assets and a repository 10 GiB (409 `asset_limit` or `storage_limit`); names must be unique within a release (409 `asset_exists`) and a body that does not match `Content-Length` is rejected and removed. `GET .../releases/:releaseId/assets/:assetId` downloads with `Content-Disposition: attachment`, `nosniff` and a sandbox CSP and follows the repository's read access; `DELETE` removes one asset. Deleting a release or purging a repository deletes the stored objects. Release changes emit `release.published`, `release.updated` and `release.deleted` events (`ReleaseEvent` in `packages/contracts/src/releases.ts`) through `emitReleaseEvent`; handlers registered with `onReleaseEvent` in the Forge worker receive them, and no webhook delivery exists yet.

Actions: `/api/actions/repositories/:id[/...]`, `/api/actions/runs/:id` and `/api/actions/runs/:id/cancel`. Starting a run beyond six per repository per hour returns 429 `run_limit` with a `Retry-After` header.

Deploy: `/api/deploy/plan`, `session`, `account`, `resources`, `provision`, `migrate` and `deploy`. See [the deployment manifest](deploy.md) for source and permission requirements.
