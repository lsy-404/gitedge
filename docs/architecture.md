# Architecture

The public Gateway authenticates browser cookies, personal access tokens (`gep_`) or agent Bearer tokens and sanitizes identity headers. It serves Vue assets and forwards requests to internal services through Service Bindings.

Auth stores only credential hashes in D1 (recovery codes, reset and verification tokens included; authenticator secrets are encrypted). It creates agent session forks through an Artifacts binding, revokes the fork's initial token, and issues a scoped token with the session's expiry. Session identity contains the owning user, agent, repository and workspace. Every privileged service verifies session scope and current membership. Personal access tokens are validated by Auth (hash, expiry, revocation); the Gateway forwards their id, scopes and optional repository allowlist as a trusted header, and Forge, Git and Actions enforce scope and allowlist per request. Native Git transport receives a write grant only for tokens holding `repo:write`.

Forge stores Issues, Pull Requests, Discussions, comments, reviews, CI checks and Wiki revisions in D1. Wiki edits use revision comparison in a database batch. PR merge coordination checks the exact head's effective review/check state and delegates Git work to the Git service. Notifications and repository webhook deliveries are written in the same D1 batch as the change that triggers them. Notification recipients are re-checked for read access when listed. Webhook deliveries are an outbox: a request that queues one delivers it immediately, and a once-a-minute cron retries with backoff. Git reports completed ref updates to Forge through an internal endpoint, so push webhooks come from receive-pack completion and from web edits and merges.

Git uses disposable Artifacts repository handles for commit, tree and file reads. Standard transport is forwarded as a stream to an exact repository endpoint with a freshly minted short-lived credential. Comparisons retain all commit parents. Merge runs isomorphic-git against an in-memory filesystem, detects conflicts, verifies expected base/head OIDs and pushes with a non-force atomic ref update.

Deploy reads a strict manifest and its declared files from Git. It binds the reviewed source digest, user, repository, ref, account and nonce into an encrypted short-lived cookie. It uses exact Cloudflare resource APIs and persists no Cloudflare credential in D1.

Actions parses `.github/workflows/*.yml` from a bounded source snapshot and runs each run in its own Container, limited in time, logs and input, with networking off by default. Git notifies it on push through `/internal/push`. Its Durable Objects use only their own storage and container. Only Actions may publish workflow check records; Forge stores them keyed to the exact commit OID.

Repository deletion is a soft delete in Forge (`deleted_at`, `purge_after`); the repository name is released by renaming the row to a tombstone slug and dropping its path aliases. Forge's scheduled purge asks Auth to revoke agent sessions, asks Git (`/internal/purge`, reachable only through the service binding) to delete session forks in bounded pages and then the Artifacts repository, and finally deletes the D1 rows. Git only deletes Artifacts repositories; Forge persists the step in `purge_state` and the fork page cursor in `purge_cursor`, so interrupted runs resume without repeating work and no distributed transaction is needed. Failed attempts are retried after a delay recorded in `purge_retry_at`.

Repository import is a Forge job in `repository_imports`. Forge claims a job, records a fresh Artifacts name for the attempt and calls Git's internal `/internal/imports`, which checks the URL, resolves the host over DNS-over-HTTPS to reject non-public addresses, and starts the native Artifacts import. Artifacts can still be copying after `import()` resolves, so status reads call `/internal/imports/status` at most once per second; when the repository is ready Git revokes every initial token and Forge inserts the repository row in one conditional D1 batch that also rechecks namespace owner access. Failed, timed-out (stuck in `starting` for 10 minutes or running for an hour) or unrecorded attempts are discarded through `/internal/imports/discard`, so a failed import leaves no repository. Artifacts exposes no credential option or size cap for imports: private sources are unsupported, and the per-repository storage limit and import memory limit (`size_limit`) are the size bound. Artifacts resolves the host again when it fetches, so the DNS check does not stop rebinding.

The MCP Worker serves `/mcp` with the official MCP TypeScript SDK's web-standard Streamable HTTP transport in stateless JSON mode: each POST builds a fresh server bound to the caller's Bearer credential, so no Durable Object or session state is kept. Tools call the public REST API through a service binding to the Gateway with that credential, so authentication, scopes, repository access and rate limits are decided exactly as for any API client; upstream responses are read with an 8 MiB bound and parsed with the contract schemas. The OpenAPI document at `/api/openapi.json` is generated from the same contract schemas.

Rate limiting uses sharded SQLite Durable Objects. Repository storage and refs remain entirely under Artifacts.

Invitations live in Forge's `invitations` table. Acceptance claims the row and inserts the membership or collaborator row in one D1 batch, so a pending invitation grants nothing and a replay cannot grant twice. Link invitations store only a SHA-256 of their token. `audit_events` is written by Auth and Forge through `src/worker/common/audit.ts` after the change it describes commits; an append failure is logged and never fails the request, and database triggers keep the table append-only. Auth owns site administration, account export and account deletion; it reads Forge tables directly from the shared database for repository listings, statistics and the export, and soft-deletes personal repositories with the same columns Forge's lifecycle uses so Forge's scheduled purge finishes the removal.

Tags, archives and raw blobs belong to Git: tags are pushed with the same short-lived write credential as branches, archives walk the tree with `readTree` and stream blobs one at a time (zip through fflate, tar through modern-tar, gzip through `CompressionStream`) through a dedicated Artifacts handle that is disposed when the response stream ends, fails or is cancelled, and raw files are served from blobs with inline types limited to text and images. Forge owns release records and the `RELEASE_ASSETS` R2 bucket: uploads stream from the request body into R2 after cheap D1 limit checks, and publishing a release asks Git to create the tag through the same authorization path as a user request. Release changes pass through an event hook in Forge; publication also queues the `release` repository webhook and an audit event.

Forks are Forge rows (`repositories.fork_of`) backed by a separate Artifacts repository created with the `fork` capability; the Git service resolves a cross-repository pull request head only from a direct fork and reuses the merge, compare and expected-OID verification of session forks. Stars (`repository_stars`, with a denormalized `star_count`), watch levels (`repository_watches`) and topics (`repository_topics`) are Forge-owned D1 tables; watchers receive `watching` notifications in the same D1 batch as the new issue, pull request or discussion.

Auto-merge settings (`forge_auto_merges`) and the registry of non-empty merge queues (`forge_merge_queues`) live in D1 and belong to Forge. Each target branch queue is a Forge `MergeQueueDurableObject` (one per repository and branch) that stores only ordering and a processing lease in its own SQLite and never calls another service. The Worker claims the head entry, runs the same merge path as a manual merge (D1 merge lease, merge policy, Git merge with expected base and head OIDs and an atomic non-force ref update) under the enabling user's identity, and reports the result back to the Durable Object. A bounded pass (at most two merges) runs after successful Forge writes and check or push events, and in the every-minute cron sweep over the least recently checked settings and queues. Races end at the claim and at the merge lease, so concurrent triggers start one merge. An enqueue registers the queue in D1 both before and after the Durable Object call, so a crash cannot hide entries from the sweep and a processor that just unregistered an empty queue cannot either; reads of unregistered queues never instantiate a Durable Object. The `/internal/merge-authorization` callback that Git makes during a merge does not start another pass.

Optional AI summaries live in Forge: a D1 queue of jobs keyed by pull request, drained by the per-minute cron so a model call is not cut off by the 30-second `waitUntil` window. A pull request never has two running jobs, and the per-repository hourly allowance is reserved with a single conditional insert. A job reads the comparison through the Git service as the requesting user, skips work when the head commit already has a cached summary, reserves a model call within the hourly limit, builds a size-bounded prompt and calls the Workers AI binding with a timeout. The result is stored in its own table, apart from reviews and comments.

## Edge caching

The Git service decides what may be cached because it checks repository visibility, deletion state, membership and token scope in D1 before every read. The Gateway forwards cache headers unchanged, defaults API responses to `private, no-store` and forces `private, no-store` on any response that sets a cookie. Each read carries `X-GitEdge-Cache` (`hit`, `miss`, `revalidated`, `bypass`) and a `Server-Timing: edge-cache` entry.

| Class                | Reads                                                                                                                                                            | Behavior                                                                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Commit-addressed     | `tree`, `file`, `files`, `blame`, `history` (cursor), `commits`, `commit-diff`, raw and archives requested by commit id                                          | `public, max-age=86400, s-maxage=3600, immutable`; JSON bodies are stored in the Cache API (`caches.default`)                                                                                                                                                                        |
| Ref-addressed        | the same reads requested by branch or tag                                                                                                                        | The ref is resolved to its commit on every request; that commit is the `ETag` and part of the cache key, so a push never needs a purge. Anonymous readers get `public, max-age=0, s-maxage=30, must-revalidate`; signed-in readers get `private, no-cache` but share the stored body |
| Listings             | `refs`, `branches`, `tags`                                                                                                                                       | Anonymous readers only: 30 second entries with a body-hash `ETag`. Signed-in readers always bypass so they see their own pushes                                                                                                                                                      |
| Private or workspace | everything in a private repository or an agent workspace                                                                                                         | Never stored or served from the cache; `private, no-store` (or `private, max-age=3600` with `Vary: Cookie, Authorization` for commit-addressed reads)                                                                                                                                |
| Not cached           | Git smart HTTP (`info/refs`, `git-upload-pack`, `git-receive-pack`), `community`, `graph`, `compare`, `pull-head`, `snapshot`, `signature`, `commit`, all writes | `no-store`                                                                                                                                                                                                                                                                           |

Raw files and archives are streamed and not stored by the Worker; they send the same headers and validators (blob id or commit id plus format) so browsers and shared caches can keep them. Entries above 1 MiB are served without being stored.

A cache key is `repository id / cache generation / Artifacts name / resource / commit or listing / sorted parameters` with no credentials. `repositories.cache_generation` is bumped by a database trigger whenever visibility, owner namespace, slug, deletion state or Artifacts storage changes, so every writer (Forge settings, transfer, rename, delete and restore, Auth account deletion, imports) starts a new keyspace without calling the Git service; earlier entries are never read again and expire on their own (a day for commit-keyed entries, 30 seconds for listings). Branch and tag reads are computed at the commit they resolved to, so a push racing a cache fill cannot store newer content under an older commit. Visibility and deletion are also re-read from D1 before every lookup. A browser or downstream shared cache that already holds a public commit-addressed response may keep it for up to `max-age` (shared caches for one hour, ref-addressed reads for 30 seconds) after a repository becomes private; nothing can purge those copies.

Pages site entries are keyed by repository, cache generation and commit in the same way and are looked up only after the public, Pages-enabled check. Forks are separate repositories with their own keyspace; cross-repository `compare` and `pull-head` reads are never cached.

Do not enable Workers Caching on the Gateway or Git Worker: it honors these `Cache-Control` headers and would answer repeat requests without running the visibility and membership checks.
