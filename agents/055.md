## 决策与范围

用户授权实现差额、降低科研优先级并重新测速，部署仅两台 Toronto AMD。基线提交 b2f0bfe756cb5da1920407005c89c89c3a011cf3；分支 codex/dynamic-idle-cpu；工作树 /Users/user/.codex/worktrees/gitedge/dynamic-idle-cpu。原 main 干净，其他工作树不变。现有不启用 CPU 目标的调用方和测试仍被支持，差额模式是新增显式能力。

整机 CPU busy 不含 idle / iowait / steal；科研服务用量由 cgroup v2 cpu.stat 计量，非科研 CPU=max(0,整机 busy-科研服务用量)。将目标总 CPU 减非科研 CPU 的差额作为服务预算，包含控制器自身的微小开销。下降立即生效，上升受限；目标满足时停止科研但保留最小控制循环配额。以 systemctl set-property --runtime 调整自己所属 service，不直接写 systemd 管理的 cgroup 文件。

初始整机目标 25%，最高配额保持现有 CPUQuota=50%（一条逻辑 CPU 口径）；在两可见线程上对应最多约 25% 整机预算。保留 OCI 7 日口径待校准的事实，不承诺短时来宾指标已证明免回收。资源门控优先于补足，科研仍可被安全暂停，复测在动态模式开启时进行。

科研进程 SCHED_IDLE 与 nice=19；控制器保留普通调度以便及时抢占。服务 CPUWeight / IOWeight=1、I/O 调度 idle，内存和磁盘上限不变。CPUQuotaPeriodSec 缩至 20ms，减小本地配额造成的长时间突发。错误停止科研，不退回无上限运行。原科研工作状态保留；部署前建立可回滚的原脚本、单元和 runtime 配额备份。

## 证据与进度

源码入口 scripts/runner-idle-load.py，安装器 scripts/runner-host-setup.sh，既有测试 test/runner-idle-load.test.mjs。新 CPU 目标模式依赖 Linux cgroup v2、root 及自身 systemd 服务；测试原模式不依赖真实 cgroup。没有新测试文件或测试用例。

Linux cgroup 官方接口：https://docs.kernel.org/admin-guide/cgroup-v2.html。systemd 资源接口：https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html。完整远端部署和复测证据保存在本设施工作区 work/dynamic-cpu，交付摘要在 outputs/network-infrastructure。

动态目标模式不再以包含科研自身排队的全机 load / CPU PSI 直接启停，避免低配额背景任务把自己反复判为外部压力。CPU 使用差额负责预算，内存 / I/O / 磁盘 / runner 门控保持；原模式的 CPU PSI 契约未改变。已有 Linux 五项测试全部通过，源码 SHA256 56e4093d99e23922871c4d59744c4a37b1e7f3cdab26e7a01daec7e6b1a239be。两台 Toronto 已部署该版，当前进行科研开启时的复测；备份及临时恢复 timer 详见设施工作区 agents/004.md。
