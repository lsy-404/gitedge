# GitHub 双向同步缺陷修复

## 目标
修复 GitHub 与 GitEdge refs 的可达同步缺陷，明确利用最后一次成功同步的 OID 选择方向；共同基线缺失或双方同时变化时保持 refs 不变并呈现可重试冲突。

## 范围
Forge ref reconciliation、既有 D1 job 历史及根目录 `test/` 下针对性测试。Issue-comment 删除路径已核实具备幂等墓碑与并发保护，本次无需变更。

## 决策依据
- 连接历史可从既有成功 `push` job 的 payload 读取；无需新增 schema。
- 初次看到相同 ref 时入队一次无操作 outbound push，成功 job 将该共同 OID 留作后续基线。
- 只保留每个连接/ref 最新成功 push job，其他完成任务仍按30天清理。
- 基线两侧仍一致时，远端/本地删除可安全传播；另一侧也变化时保留数据并记录 `concurrent_ref_changes` 冲突。冲突重试时重新读取两侧 refs 与基线。

## 当前结果
实现与针对性回归通过；本地提交后交由父任务集成。
