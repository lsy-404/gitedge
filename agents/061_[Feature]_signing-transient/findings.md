# Findings
OIDC and GitHub run validation remain admission controls. R2 multipart parts are 8 MiB. Durable Object alarms enforce source and delivery-cache retention; R2 lifecycle is a fallback whose deletion can be delayed. Existing immutable profile snapshots still include artifactName, which no longer participates in transport.
The signing integration initially failed on an unsupported inter-TransformStream pipe; bounded per-part buffering fixed the actual upload path. Old tests required adaptation to the new contract.
Worker CI failure on fail callback: the test coordinator stub exposed fetch only, but the callback now invokes releaseSource after recording failure. Extend the existing stub and assert both original and replay cleanup calls; no production code change was needed.
Production source upload failure investigation: source PUT reads a bounded 8 MiB body and uses Web Crypto before R2 uploadPart; the DigestStream/FixedLengthStream code applies to runner output, not source. The existing Worker integration was expanded to use an 8 MiB part and 17-byte final part, with both parts, completion digest and queueing passing. A local pass does not establish network or production behavior.
