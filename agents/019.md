## Decisions and findings

- Base: origin/main 4adf8bd. Worktree: codex/runner-host-replacement under the configured Codex worktree root. Preserve unrelated checkouts and changes.
- The final request is one Mac runner and two ordinary Windows runners. Each registration has one slot and independent state, installation and persistent service. No scheduler/schema rollout is needed for this capacity increase.
- The Mac is macOS 26.7.1 arm64 with 10 logical CPUs and 24 GiB RAM. No OS or Xcode changes were made. Its existing LaunchAgent and toolchain environment were retained.
- Windows is the previously accessed Windows 11 Pro x64 host with eight logical CPUs and approximately 24 GiB RAM. Preserve the existing 64 GiB pagefile and interactive-session tool environment. Reuse Node 24.22.0, pnpm 10.34.6, PowerShell and Rust MSVC from the existing tool installation.
- Preserve the separate Windows signing runner and its credentials. All new GitEdge profiles explicitly use executionClass=ordinary. The existing Mac routing labels were copied during equivalent rotation; no dedicated signing approval was granted.
- The requested SSH login was saved in the user's 1Password Private vault and verified without exposing its value. No Keychain item was created or modified; the preexisting Windows App credential was preserved. Connected 1Password tools support Environments, not vault Login CRUD, so the initial save used the CLI. Subsequent SSH operations reused one established control connection and did not read the secret again. No 1Password Connect server was provisioned.
- Same-origin requests inside the authenticated browser performed native API operations. Automatic review rejected cookie export; no session cookie was exported. The equivalent registration rotation was accepted after confirming that inherited labels do not grant dedicated signing authority.
- Actual Mac execution initially exposed os.freemem() excluding reclaimable inactive pages. Bounded vm_stat output now reports free + inactive + speculative pages with the host page size. Scheduling thresholds remain unchanged. Primary references: Apple vm_stat and XNU counters; psutil macOS available-memory calculation.
- Actual Windows execution passed pnpm, but capacity discovery omitted it because direct Node spawn cannot launch a .cmd shim. The allowlisted Windows pnpm version probe now invokes cmd.exe /d /c pnpm.cmd --version; other tool probes are unchanged.
- Windows scheduled-task termination can leave broker locks. Both host launchers inspect only their own state/actions locks and remove a lock only when its recorded positive PID no longer exists. Live or malformed lock ownership fails closed. Synchronized restart verified recovery without manual lock deletion.
- Initially misunderstood the capacity target as Mac. The unused second Mac registration was revoked before any second service started, and its task-created directories were removed. Final local checks confirm no second Mac installation, state directory or LaunchAgent.
