# SynthV GitEdge consumer migration

## Scope

Migrated the SynthV desktop release consumer to GitEdge's native GitHub artifact pull contract. The source workflow uploads the `signing-source` artifact and passes its GitHub artifact ID; GitEdge downloads and validates the complete ZIP. No production dispatch, signing, push, or deployment was performed.

Repository: `SynthVCopilot/synthv-toolbox` (repository ID `1319908050`)
Source workflow: `.github/workflows/desktop.yml`
Publish workflow: `.github/workflows/desktop-macos-publish.yml`
GitEdge profile: `synthv-macos-arm64`

## Changes

- Replaced the old signing-center multipart upload with an OIDC-authenticated GitEdge request bound to repository, stable tag run, commit, artifact ID, digest, size, profile, version, and idempotency key.
- Added bounded retries for transient request failures using the same request body and idempotency key; authorization and other non-transient client failures stop immediately.
- Replaced publish polling and output transfer with native request status and output download validation. The fetch path checks request/profile/source binding, response digest and size, and downloaded bytes.
- Kept final report binding to request ID, platform, final stage, output files, and all existing signature, Team ID, notarization, staple, and Gatekeeper validations. Per the agreed multi-stage contract, the report `input_digest` is format-checked as the prior-stage digest; authenticated status separately binds the original source digest.
- Updated release process documentation and contract tests.
