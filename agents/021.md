## Decisions and findings

- Rosmontis explicitly requested GitEdge native signing also use general-purpose runners and task-delivered secrets. The preceding host-only migration is insufficient for this scope.
- Three newly installed brokers are ordinary/general-purpose registrations, while the old Windows signing listener remains. Existing GitHub signing workflows use protected environment secrets; native Actions currently instead gates on a dedicated registration and owner host approval. No implementation changes were made before clarifying these distinct paths.
- Remove executionClass, dedicated-host approval routes/metadata and the claim execution-class header. A job identifies its executor with run.kind=workflow|signing|github; the host registration has one general capability.
- Signing jobs retain their fixed trusted platform SDK and approved immutable profile/source validation. Queue them with actual platform/tool requirements; do not require a machine to be online at submission. Namespace/repository scope, current owner, revocation, cancellation, lease expiry, exact stage/generation/nonce and profile revision remain authorization boundaries for secrets.
- Remove host operatorApproval snapshots from D1/DO records and wire contracts. Existing encrypted platform/source credential storage remains authoritative. Apply forward data changes without compatibility APIs or a second execution path.
- Windows native credentials use tenant_id/client_id/client_secret from the protected profile secret store. Deliver them only to the current lease; pass AZURE_TENANT_ID/AZURE_CLIENT_ID/AZURE_CLIENT_SECRET only to the signing child processes, enable Azure EnvironmentCredential and disable all machine/user credential fallbacks. Microsoft documents this integration for machines outside Azure. No credentials will be printed or committed.
- Separate Windows platform runtime work and web/docs work are independent non-mechanical implementation streams after this shared contract decision. Delegate only these streams in isolated worktrees; the main agent owns architecture, backend/contracts, broker integration, audits and adversarial validation. Use the lower-tier allowed model as required by repository instructions.
- Existing tests only: revise assertions when the requested public contract changes; preserve checks that ordinary jobs cannot request signing secrets and a signing job cannot authorize another request or lease.
